## Considered options

### Install the harness in layers, rules measured first (recommended)

- Good: every rule starts from what the code does today; nothing is imposed that was not confirmed.
- Bad: more questions up front.

### Write only the guides

- Good: fast.
- Bad: nothing checks that the guides are followed.

## Decision outcome

Chosen: the harness in layers: `kh` pinned in `.agents/keel.lock`, scripts and gates in `.agents/keel.yml`, `AGENTS.md` as an index,
the agent hooks in `.claude/settings.json`, the git hooks, and an independent review that is always offered. Confirmed by
{{who}} on {{YYYY-MM-DD}}.

## Consequences

- Secrets: `.gitleaks.toml` allow-lists these git-ignored directories: {{dirs, or "none: nothing ignored holds files"}}. Changing it is a loosening and needs an ADR.
- Protected files change only when a human confirms the edit.
- A rule is loosened only by an ADR that names it; accepted ADRs are never edited.
- `sh .agents/bin/kh check` reports when the harness drifts from the repository.
